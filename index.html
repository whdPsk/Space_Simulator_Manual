Chapter 02

Getting Started

Mission Control · Start to Launch

GPU 노트북에서 Start-RemoteResearch.ps1을 PowerShell로 실행한 뒤, 휴대폰이나 다른 PC에서도 아래 주소로 접속합니다. Show-ResearchLogin.ps1에서 확인한 전용 키로 로그인하세요. Cloudflare 비밀번호와는 별개입니다. 개인 기기에서는 Keep me signed in for 90 days를 선택하세요. 이미 로그인했다면 콘솔 상단의 같은 버튼으로 키 재입력 없이 연장할 수 있습니다. 로그아웃·쿠키 삭제·기간 만료·다른 브라우저에서는 다시 로그인합니다.

Open Research Console ↗

cosmos.whdpsk.workers.dev/start · 매뉴얼은 같은 주소의 /manual입니다. 설계·대기열은 자동으로 준비하고 Start experiment를 눌러야 한 실험의 검증·GPU 계산·분석을 진행합니다. 노트북이 켜져 있고 연결 프로그램이 실행 중이어야 합니다. 재부팅 후에는 다시 실행하세요.

결과·보고서는 비공개 Drive의 Research_Archive/outputs에 저장합니다. 원격 사이트에는 간단한 제어 상태만 전송합니다. 노트북에서만 접속할 때는 Start-ResearchConsole.ps1 → Local Console도 사용할 수 있습니다.

# 스크립트 대신 터미널에서 콘솔 시작
.\.venv\Scripts\python.exe -X utf8 -m automation.console

Windows PowerShell에서 저장소 루트로 이동합니다. 계산은 Windows의 Python 가상환경에서, Claude Code만 WSL에서 실행합니다.

git clone https://github.com/whdPsk/Space_Simulator.git
cd Space_Simulator
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
# NVIDIA GPU가 있는 Windows 실행 환경에서만 설치
.\.venv\Scripts\python.exe -m pip install "cupy-cuda12x[ctk]"

기존 PC에는 설정된 가상환경을 그대로 사용합니다. 재현 시 패키지 버전은 requirements_lock.txt와 실행 manifest를 함께 확인하세요. GPU 계산은 적합한 NVIDIA 드라이버가 필요합니다.

RequirementHow to Check
GPU & Available VRAMnvidia-smi
Claude Subscription LoginWSL에서 claude auth status
Codex Logincodex login status

config.local.json은 Git에서 제외합니다. CLI 경로·환경 ID만 넣고 인증 토큰이나 API 키를 저장하지 않습니다. Claude는 구독 로그인만 사용하며 API 과금 방식으로 자동 전환하지 않습니다.

Chapter 03

Research Workflow

  1. Experiment DesignQuestion · Model · Seed · Grid · Compute Budget
  2. GPU Validation & ExecutionStart → 16³ smoke → 256³ smoke → queued experiment
  3. Numerical AnalysisHash · Mass · Phase · Initial Representation · Power Difference
  4. Claude Interpretation공개 논문 검색·열람 → 물리 가설과 직관 설명
  5. Codex Review독립 해석 → 오류 지적 → 최대 2회 수정
  6. Archive & Next Experiments보고서 · 다음 실험안 · Drive 보관 · 코드 이력

로컬 제어기는 작업 순서와 예산을 관리합니다. 에이전트가 만든 문장을 셸 명령으로 실행하지 않습니다. 실행기는 정해진 실험만 수행하고, 다음 세대 실험은 설계로 남깁니다. 새로운 모델이나 더 큰 grid는 실행 정책을 확장한 뒤 진행합니다.

Agent Roles: Claude Code, Cowork & Codex Cloud

Claude Code는 문헌 조사와 구조화된 해석을 수행합니다. Cowork에서는 보관된 보고서를 열어 연구 노트·발표 자료를 정리할 수 있습니다. Cowork 대화 메모리가 CLI로 자동 공유되지는 않습니다. Codex Cloud는 GitHub 소스를 읽고 CPU 검증·검토를 수행하는 별도 작업 환경입니다. 노트북 GPU 계산을 Cloud로 옮기는 기능은 아닙니다.

Chapter 04

GPU Experiments

현재 콘솔의 첫 후보는 N256 · phase 0.4→0.2 · PM 1280 / SP 640입니다. 8 Mpc/h · seed 12 · m22=0.1 · z=49/19/9를 유지합니다. N384와 더 큰 예산은 설계로만 남깁니다. 총 2시간, 본런 40분, 산출물 20 GiB 상한이며 시작 전 15 GiB 여유가 필요합니다. 완료한 R-9 묶음을 자동 반복하지 않습니다.

AI 분석 체크박스를 선택하고 Start를 누르면 수치 요약과 초안·피드백을 Claude/Codex에 보내 문헌 조사·해석·최대 두 번 수정·재검토까지 수행합니다. 원자료·소스·인증정보는 분석 입력에서 제외합니다. 체크 해제 시 수치 분석과 오프라인 보고서까지만 수행합니다. 아래 명령은 이전 R-9 묶음 재현용입니다.

# 실행 계획만 확인 — 계산을 시작하지 않음
.\.venv\Scripts\python.exe -m automation.campaign

# 실제 GPU 계산 + 수치 분석 + Drive 복사
.\.venv\Scripts\python.exe -m automation.campaign --execute --analysis-mode offline --drive-root "G:\내 드라이브\project\Space Simulation\Research_Archive"

Drive 경로는 본인 PC에서 연결된 기존 폴더로 바꾸세요. 다른 PC에서는 이전 192³ 기준 결과를 복원하고 --baseline <결과 폴더>을 지정해야 합니다. Git에는 원자료가 포함되지 않습니다.

ExperimentGridPhase CapMinimum PM / SP Steps
Baseline192³0.8320 / 160
Spatial Check256³0.8320 / 160
Temporal Check A192³0.4640 / 320
Temporal Check B256³0.4640 / 320

GPU는 한 번에 한 작업만 사용합니다. 새 프로세스의 실행 시간은 최대 40분, GPU 묶음은 실행 간 확인하는 2시간 예산을 갖습니다. 시작 시 로컬 여유 공간 15GiB를 요구하고, 실행 사이에 출력 20GiB와 여유 공간을 다시 확인합니다. 이 저장 한도는 개별 파일 쓰기를 실시간 차단하는 할당량은 아닙니다. 계산 중 창을 닫거나 절전하면 실행이 중단될 수 있습니다.

코드 또는 기존 기준 결과가 바뀌면 계산을 멈춥니다. 물리 코드를 수정한 뒤에는 새 기준 실험과 대조 실험을 같은 소스로 다시 실행해야 합니다.
Chapter 05

Interpretation & Literature

외부 AI 전송을 승인한 분석에서 local 모드를 선택하면, 작은 수치 요약과 근거 ID를 Claude Code에 보내 논문 조사와 해석을 요청합니다. Codex가 수치·문헌·가설·비유를 검토하고, 필요한 경우 최대 두 번 수정합니다.

# 이미 만들어진 suite_summary.json을 해석
.\.venv\Scripts\python.exe -m automation.research "outputs\campaigns\작업ID\analysis\suite_summary.json" --mode local --max-revisions 2 --config automation/config.local.json

검색어에는 비공개 경로·수치를 넣지 않도록 지시하고, 인용할 공개 원문을 실제로 열었는지 기록합니다. 검색 결과 요약만으로 문헌을 채택하지 않습니다. 문헌을 열었다는 사실과 주장을 뒷받침한다는 판단도 구분합니다.

FilePurpose
report.md수치 판정·해석·검토·다음 실험을 한 번에 읽기
evidence.json주장이 실제 어떤 수치와 연결되는지 확인
interpretation.json관측 사실 / 물리 가설 / 직관적 비유 구분
review.jsonCodex 독립 해석과 accept / revise 이유
next_experiments.json예측·반증 검사·사전 판정 기준이 있는 다음 설계

accept는 해석 초안의 검토 통과입니다. 물리적 수렴이나 관측 예측의 검증 완료를 뜻하지 않습니다. 수정 예산을 다 쓰면 revision_required를 남기고 멈춥니다.

Space_Simulator/
├─ simulation_real/          Physics source
├─ automation/               Research workflow controller
├─ site/                     Public handbook
└─ outputs/                  Junction → Drive Research_Archive/outputs
   ├─ console_runs/작업ID/   New runs, logs, numerical analysis & plots
   ├─ fdm_research/          Previous FDM campaigns
   ├─ campaigns/작업ID/      GPU experiment suite
   │  ├─ spatial256/        256³ raw data & manifests
   │  ├─ temporal192/       192³ temporal control
   │  ├─ temporal256/       256³ temporal control
   │  └─ analysis/          Comparison JSON, figures & reports
   ├─ automation/분석ID/     AI interpretation, review & references
   ├─ cloud/                Cloud requests & task IDs
   ├─ cloud_collections/    Cloud responses & review diffs
   └─ archives/             Inventory, checksums & receipts

원자료 NPZ에는 밀도 지도와 power spectrum이 들어 있습니다. manifest는 설정·진행 상태·소스 hash·산출물 hash를 기록합니다. source_snapshot/은 실행한 소스의 정확한 바이트입니다. 기존 출력은 덮어쓰지 않습니다.

Drive as Primary Storage

새 결과는 G:\내 드라이브\project\Space Simulation\Research_Archive\outputs에 직접 생성됩니다. Google Drive 데스크톱 앱이 업로드합니다. 기존 코드의 outputs는 이 폴더로 연결되어 과거 경로를 유지합니다. 코드·가상환경과 작은 실행 상태 .research_state/는 PC에 남습니다.

기존 결과 이전은 파일별 SHA-256 사본 검사와 별도 복구 ZIP의 원격 바이트 검증을 거친 뒤 C: 원본을 정리합니다. 과거 과학 기록은 바꾸지 않습니다. Drive를 스트리밍 모드로 사용해도 캐시가 C: 공간을 사용하므로 결과 폴더를 오프라인 사용으로 고정하지 않는 것이 좋습니다.

Optional Recovery Archives

추가 ZIP64 보관은 선택 사항입니다. 기존 automation.archive 명령 자체는 원본을 삭제하지 않습니다.

# 완료된 개별 결과를 나중에 추가 보관
.\.venv\Scripts\python.exe -m automation.archive "outputs\automation\분석ID" --drive-root "G:\내 드라이브\project\Space Simulation\Research_Archive"
local_copy_verified_remote_pending

Drive 폴더에 쓴 바이트 검증 완료. Google 서버 보관 확인은 아직입니다.

remote_present_integrity_pending

서버의 파일 이름·크기·위치는 확인했습니다. 연결 도구가 원격 checksum을 제공하지 않아 내용 대조는 미완료입니다.

remote_verified

Drive API가 크기와 MD5를 제공할 때 사용하는 추가 보관 도구의 검증 상태입니다. 현재 연결 도구가 checksum을 생략하면 이 상태로 승격하지 않습니다.

remote_download_verified

이전용 복구 ZIP을 서버에서 다시 읽어 전체 크기와 SHA-256을 대조했습니다. 이 증명이 있어야 기존 원본 정리 단계가 열립니다.

Drive 앱이 오프라인이거나 동기화가 멈추면 업로드는 대기합니다. 서버의 이름·크기 확인과 원격 내용 검증을 구분하며 로컬 복사만으로 완료라고 표시하지 않습니다. 연결 도구의 다운로드 한도를 넘는 복구 ZIP은 브라우저로 받은 뒤 SHA-256을 확인합니다. 중단된 .partial 파일은 완료본으로 사용하지 말고 새 보관 실행을 생성하세요.

Chapter 07

Codex Cloud

앱의 게시된 Cloud 환경과 CLI가 표시하는 환경 목록을 먼저 구분합니다. 앱에서는 해당 환경을 선택해 작업하고, 시작할 때 실제 Git commit을 확인합니다. Publish 완료만으로 기존 작업이 최신 소스로 바뀌거나 CLI 자동화에 연결됐다고 판단하지 않습니다.

CLI Connection codex cloud의 환경 선택 목록에 대상 저장소가 있는지 확인하세요. 그 목록의 ID를 codex_cloud_environment_id에 기록합니다. 앱의 작업 딥링크(codex://threads/…)나 실행 인스턴스 ID를 대신 넣지 않습니다. 대상이 없으면 아래 CLI 명령을 실행하지 말고 앱 환경과의 호환성을 확인하세요.
# 현재 원격 main 커밋을 CPU 테스트하는 Cloud 작업 제출
.\.venv\Scripts\python.exe -m automation.cloud --config automation/config.local.json submit --branch main

# 완료된 작업의 결과를 로컬 기록으로 가져오기
.\.venv\Scripts\python.exe -m automation.cloud --config automation/config.local.json collect "outputs\cloud\작업ID"

제출은 한 번만 수행하고 작업 ID·원격 commit·요청문을 보관합니다. 결과 diff는 검토 자료로 수집하며 자동으로 소스에 적용하지 않습니다. 응답이 불명확한 제출은 중복 실행을 피하기 위해 자동 재시도하지 않습니다.

Interpretation Review in Codex Cloud

automation.research --mode cloud-handoff는 Claude 초안과 검토 요청을 준비합니다. 전송을 승인한 분석 폴더를 automation.cloud submit --review-folder <분석 폴더>에 넘기면 Cloud에 검토를 요청합니다. 이 경로의 결과 수집은 검토 자료까지이며 로컬의 자동 수정 루프와는 별개입니다.

Chapter 08

Numerical Validation

DiagnosticCriteria & Scope
Mass & Phase질량 상대오차 10⁻⁸ 이내, 위상 상한 준수. 오류 검출용이며 power 정확도 보장은 아닙니다.
Initial Representation각 grid 안의 초기 |Pwave/Pcold − 1| ≤ 5%. 두 초기 상태가 같은지 보는 기준과 다릅니다.
Spatial Sensitivity공통 물리 k 셸에서 파동·입자 power와 비율을 각각 비교. 탐색 기준 10%.
Temporal Sensitivity같은 grid에서 시간만 세분화하여 세 양을 각각 비교. 탐색 기준 1%.
High-k Occupancygrid별 2/3 Nyquist 위 파동 노름 1%는 경고. grid가 달라지면 물리적 문턱도 달라집니다.

차이는 기준 / 세분화 − 1로 정의합니다. 더 촘촘한 결과도 참값으로 가정하지 않습니다. 조건을 통과한 연속 k 대역을 기록하되, 두 grid와 한 단계 시간 검사만으로 점근적 수렴을 주장하지 않습니다.

Model Limitations
작은 주기적 상자와 제한된 seed의 탐색입니다. 초기 속도는 CDM 성장모드 근사이며 가스·별·피드백·별 형성 계산이 없습니다. 전체 복소 파동함수와 입자 phase space checkpoint를 저장하지 않아 직접적인 전체 초기 상태 대조와 중간 재시작은 지원하지 않습니다.

References

  • Hu, Barkana & Gruzinov (2000) — FDM의 선형 억제와 물리적 길이 척도.
  • May & Springel (2021) — 우주론 파동 계산의 시간·공간 해상도 제약.

공개 논문은 방법과 가설을 검토하는 자료입니다. 논문의 결론을 이번 계산의 검증 결과로 대신 사용하지 않습니다.

Chapter 09

Troubleshooting

Stopping a Run

실행한 터미널에서 Ctrl+C를 누릅니다. 제어기는 실행 중인 자식 계산을 종료하고 실패 기록을 남깁니다. 이미 완료된 실험과 보관본은 유지합니다. 전체 ψ checkpoint가 없어 진행 중이던 실험은 새 폴더에서 처음부터 다시 실행해야 합니다.

GPU Out of Memory / Timeout

작업 폴더의 해당 실험 .log와 failure.json을 확인합니다. 자동으로 정밀도·phase cap·grid를 바꾸지 않습니다. 다른 GPU 작업을 종료한 뒤 예산을 검토하고 다시 실행하세요. 두 제어기를 동시에 실행하면 GPU 잠금으로 한쪽을 중단합니다.

Claude Authentication / Usage Limits

WSL에서 claude를 열어 로그인 상태를 복구합니다. API 키 과금으로 우회하지 않습니다. 성공한 초안이 있으면 동일 근거에 대해 --resume-draft <이전 분석 폴더>로 재사용할 수 있습니다. 다른 결과의 초안을 재사용하면 hash 검사에서 거부합니다.

Published Cloud Environment Missing from CLI

앱 환경의 게시 여부와 CLI 환경 목록은 별도로 확인합니다. 다른 저장소의 환경 ID나 앱 작업 ID를 대신 쓰지 마세요. 앱에서 작업할 때도 실제 commit과 필요한 코드가 있는지 확인한 뒤 테스트합니다. 새 작업이 최신 소스를 사용하는지는 실행 시 확인해야 합니다.

Codex Cloud: Git / Proxy Connection Failure

Repository is not accessible이면 GitHub 연결의 저장소 권한을 확인합니다. Failed to connect to proxy port 8080이면 Cloud 내부 프록시 연결 문제이므로 인증 실패로 단정하지 않습니다. 지원되는 환경 복구 경로를 사용하고 프록시·TLS·인증 설정을 우회하지 마세요. 제출 응답이 불명확하면 먼저 codex cloud list --json로 중복 작업 여부를 확인합니다.

Drive Upload Pending Verification

Drive 폴더 저장은 동기화 시작이지 서버 업로드 완료 증명이 아닙니다. Drive 앱 상태를 확인하세요. 이전 도구는 원격 복구 ZIP 내용이 검증되기 전에는 원본을 지우지 않습니다. Drive 연결이 없으면 콘솔 Start는 차단됩니다. 인터넷 단절 시 Drive 캐시의 업로드가 대기할 수 있습니다.

Console Offline / Interrupted Mission

원격 접속은 노트북에서 Start-RemoteResearch.ps1을 실행하세요. 45초 이상 연결 신호가 없으면 Start가 비활성화됩니다. 요청은 90초 안에 한 번 전달하고 자동 재전송하지 않습니다. 로컬 접속은 Start-ResearchConsole.ps1 또는 python -m automation.console을 사용하세요. 실패한 작업은 같은 plan ID로 자동 재시도하지 않습니다. .research_state/jobs/작업ID/worker.log와 결과 폴더의 failure.json을 확인하고 원인·재실행 범위를 검토하세요. Notion 기록은 별도 단계입니다.

Proposed 384³ Experiments

현재 실행기는 256³까지입니다. 제안된 384³는 자동 실행되지 않으며 8GB GPU에 맞는다고 가정하지 않습니다. 메모리·시간·저장 예산을 별도로 검토하고 초기 상태와 대조 실험을 설계한 뒤 실행 정책을 확장해야 합니다.

Reproducibility

소스·테스트·사용 문서는 GitHub, 대용량 연구 결과는 Drive에 보관합니다. PC에는 코드·가상환경·작은 제어 상태와 Drive가 관리하는 캐시가 남습니다. GitHub Actions는 push마다 CPU 제어기 테스트를 실행합니다. 매뉴얼은 별도 공개 저장소 Space_Simulator_Manual에 게시합니다. python -m automation.publish_manual --publish가 site의 HTML·CSS·JS·.nojekyll 네 파일만 올리고, 해당 저장소의 main 루트를 GitHub Pages가 자동 배포합니다.

# 변경 내용을 먼저 확인하고, 의도한 파일만 추가
git status --short
git diff
git add automation site .github/workflows
git commit -m "Update research automation and manual"
git push origin main

Windows 로컬 Git을 사용합니다. 결과와 PC 설정을 일괄 추가하지 마세요. 실행 기록은 Notion의 코드 변경 Ch.N과 결과 R-N으로 구분하고, 결과에는 설정·수치·그림·재현 명령·tag를 남깁니다. 과거 commit되지 않은 실행을 현재 코드의 tag로 소급 표시하지 않습니다.
